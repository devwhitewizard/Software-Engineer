# How to Use the API Routes with Postman

Before testing the endpoints, make sure your Express server is running.

For example:

```bash
node server.js
```

Assuming your server runs on port `3000`, the base URL is:

```text
http://localhost:3000
```

Replace the port if your application uses a different one.

## A. Register a New User

**Method:** `POST`

**Endpoint:**

```text
http://localhost:3000/api/auth/register
```

**Postman steps:**

1. Open Postman.
2. Select `POST`.
3. Enter the registration endpoint.
4. Go to Body.
5. Select `raw` and choose `JSON`.
6. Enter the user details.

**Example request body:**

```json
{
    "email": "test@example.com",
    "password": "password123"
}
```

**Purpose:** Creates a new user account.

Try registering another user with the same email to see how the API handles duplicate accounts.

## B. Login

**Method:** `POST`

**Endpoint:**

```text
http://localhost:3000/api/auth/login
```

**Postman steps:**

1. Select `POST`.
2. Enter the login endpoint.
3. Go to Body.
4. Select `raw` and `JSON`.
5. Enter the registered email and password.

**Example request body:**

```json
{
    "email": "test@example.com",
    "password": "password123"
}
```

**Purpose:** Checks the user's credentials and, when successful, returns authentication tokens according to the login flow.

Copy the access token and refresh token from the response for the next steps.

## C. Get Current User

**Method:** `GET`

**Endpoint:**

```text
http://localhost:3000/api/users/current
```

**Postman steps:**

1. Select `GET`.
2. Enter the endpoint.
3. Open the Authorization tab.
4. Select `Bearer Token`.
5. Paste your access token.
6. Click Send.

**Purpose:** Returns information about the currently authenticated user.

This endpoint helps me understand how authentication middleware protects routes.

## D. Refresh Access Token

**Method:** `POST`

**Endpoint:**

```text
http://localhost:3000/api/auth/refresh
```

**Postman steps:**

1. Select `POST`.
2. Enter the refresh endpoint.
3. Go to Body.
4. Select `raw` and `JSON`.
5. Provide the refresh token.

**Example request body:**

```json
{
    "refreshToken": "YOUR_REFRESH_TOKEN"
}
```

**Purpose:** Requests a new access token using a valid refresh token.

If refresh token rotation is implemented, the response should also provide a replacement refresh token.

Remember to use the latest refresh token after a successful refresh.

## E. Generate a 2FA QR Code

**Method:** `GET`

**Endpoint:**

```text
http://localhost:3000/api/auth/2fa/generate
```

**Postman steps:**

1. Select `GET`.
2. Enter the endpoint.
3. Open Authorization.
4. Select `Bearer Token`.
5. Paste your access token.
6. Click Send.

**Purpose:** Generates a QR code for setting up two-factor authentication.

The response is an image rather than ordinary JSON.

In Postman, use the response preview or save the response as a file to inspect the QR code.

Scan the QR code using an authenticator application.

## F. Validate 2FA OTP

**Method:** `POST`

**Endpoint:**

```text
http://localhost:3000/api/auth/2fa/validate
```

**Postman steps:**

1. Select `POST`.
2. Enter the endpoint.
3. Add your access token under Authorization as a Bearer Token.
4. Go to Body.
5. Select `raw` and `JSON`.
6. Enter the current code from your authenticator application.

**Example request body:**

```json
{
    "totp": "123456"
}
```

**Purpose:** Checks whether the submitted OTP matches the user's 2FA secret.

The example code above is only a placeholder. Use the current code generated by your authenticator application.

## G. Logout

**Method:** `POST`

**Endpoint:**

```text
http://localhost:3000/api/auth/logout
```

**Postman steps:**

1. Select `POST`.
2. Enter the logout endpoint.
3. Add the access token using Bearer Token authentication.
4. Provide the refresh token in the request body if your implementation expects it.
5. Click Send.

**Example request body:**

```json
{
    "refreshToken": "YOUR_REFRESH_TOKEN"
}
```

**Purpose:** Logs the user out by invalidating the relevant tokens according to the application's logout implementation.

After logging out, try accessing a protected endpoint with the old access token to test whether it is rejected.

## H. Access the Admin Route

**Method:** `GET`

**Endpoint:**

```text
http://localhost:3000/api/admin
```

**Postman steps:**

1. Select `GET`.
2. Enter the admin endpoint.
3. Add a valid access token under Authorization.
4. Click Send.

**Purpose:** Tests role-based authorization.

Only a user with the required administrator role should be allowed access.

## I. Access the Moderator Route

**Method:** `GET`

**Endpoint:**

```text
http://localhost:3000/api/moderator
```

**Postman steps:**

1. Select `GET`.
2. Enter the moderator endpoint.
3. Add a valid access token under Authorization.
4. Click Send.

**Purpose:** Tests whether the user has the moderator role.

A user can be authenticated but still be denied access if they do not have the required role.

## 7. Recommended Testing Order

For a first-time learner, I can test the endpoints in this order:

1. Register a new user.
2. Log in with the registered credentials.
3. Copy the access token and refresh token.
4. Access `/api/users/current` using the access token.
5. Try accessing `/api/admin` and `/api/moderator`.
6. Generate a 2FA QR code.
7. Scan the QR code with an authenticator application.
8. Submit an OTP to the validation endpoint.
9. Test the refresh token endpoint.
10. Log out.
11. Try accessing a protected route with the old access token.

**Important:** Test with accounts you control. Use placeholder credentials in this README, never real passwords or tokens.
